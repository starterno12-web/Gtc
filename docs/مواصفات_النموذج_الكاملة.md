# مواصفات محرك نواة — الوصف الكامل

**هذا المستند وصف هندسي (بنية + إعدادات + ميزات) — ما فيه ولا رقم وزن واحد.** الأوزان الفعلية (الأرقام
اللي النموذج تعلّمها) تعيش بملف ثنائي منفصل تمامًا (`nlm2.bin`، 5.95 ميجا) ما ينكتب كنص. يعني لو
حذفت `nlm2.bin`، هذا الوصف **يبقى صحيحًا بالكامل** — لأنه يوصف الآلة (المحرك)، مو محتوى ذاكرتها.

---

## 1) البنية (Architecture)

| الخاصية | القيمة |
|---|---|
| النوع | GRU متكرر (Recurrent) — **مو** Transformer، صفر نافذة سياق ثابتة |
| التطبيق | كوتلن (`Nlm.kt`, على الجوال) + توأم بايثون مطابق رياضيًا (`nuwaa/lm/gru.py`, للتدريب على GitHub) |
| embed (الحالي) | 64 |
| hidden (الحالي) | 384 |
| المفردات (vocab) | 188 رمز (حرفي، مو byte-level) |
| المعاملات (الحالي) | ~1.49 مليون (أوزان + انحيازات) |
| الذاكرة الصريحة | نظام n-gram مزدوج (`long`/`short`) منفصل عن حالة الشبكة — يحتفظ بنص كل رسالة فعليًا، يقلل الاعتماد على ذاكرة GRU المحدودة |
| السياق | **بلا سقف صلب وقت الاستخدام** (خاصية GRU الأساسية) — الاحتفاظ الفعلي للمعلومات البعيدة محدود بحجم حالة GRU (384) لا بسقف برمجي |

## 2) النمو الديناميكي (`growModel`)

- يكبّر `embed`/`hidden` وقت التشغيل، بدون إعادة تدريب كاملة
- سقف الذاكرة: 80% من حد التطبيق (كان 60%) — مطابق لـ `android:largeHeap="true"` المفعّل بالمانفست
- حد الرام الكلي (`ramSoftLimit`): 3.2 جيجا (كان 1.2 جيجا)
- **حماية جديدة:** بعد كل تكبير، فحص سلامة إجباري (`ModelHealth`) — كل الأوزان أرقام سليمة (لا NaN/Inf) + 3 أسئلة اختبار حقيقية. فشل الفحص = تراجع تلقائي فوري، صفر حفظ لنسخة مكسورة. هذا الفحص **كان غائبًا كليًا** قبل هذا التطوير.

## 3) التطوير الذاتي (`develop`)

- يعيد التدريب على محادثات المستخدم الفعلية، بمعدل تعلّم ثابت بالكود
- يقيس نفسه قبل/بعد (بت/حرف) ويحتفظ بالتحسين **فقط لو تحسّن فعليًا** — موجود من الأصل
- **حدود هيكلية (فيزيائية لا برمجية):** يعدّل فقط مصفوفات أرقام عائمة بالذاكرة. ما عنده وصول لملفات، شبكة، أو كود Kotlin آخر — لا يقدر يغيّر شروطه أو أي إعداد حماية، لأن القدرة غير موجودة بالتصميم من الأساس

## 4) خطة الجهد (`Effort.plan`) — كل رقم مُعدّل وسبب التعديل

| المستوى | الحرارة | أقصى طول | محاولات | يتفعّل متى |
|---|---|---|---|---|
| FAST | 0.25 (كان 0.55) | 300 حرف (كان 180) | 1 | فقط لو الجهاز بوضع توفير طاقة |
| NORMAL | 0.30 (كان 0.70) | 900 حرف (كان 450) | 1 | فقط لو الجهاز بحالة غير مثالية |
| THINK | 0.30 (كان 0.70) | 2000 حرف (كان 900) | 4 (ثابت، لا يقل بسبب الوقت) | **الافتراضي لكل رسالة**، حتى "هلا" |
| THINK-كود | 0.15 (جديد كليًا) | 6000 حرف (جديد) | 8 (جديد) | رسالة فيها كلمة كود/برمجة/```/function/إلخ |
| أخذ العينات | topk=4, minP=0.25 (كانت 8 / 0.15) | — | — | كل الأوضاع — اختيار أضيق وأحسم |

- **حماية الحرارة:** أُزيلت بطلبك الصريح (عندك مروحة خارجية)
- **حماية البطارية والرام:** باقية بدون تغيير — السبب مختلف تمامًا عن الحرارة، ما لهم علاقة بتفضيل سرعة

## 5) إصلاح خلل حقيقي في `replyThink`

كان يتجاهل كل الإعدادات أعلاه: جدول حرارة ثابت بالكود (0.55-0.85) وسقف خفي 5 محاولات بغض النظر عن
الطلب. صار يستخدم حرارة المستدعي فعليًا وينفّذ بالضبط عدد المحاولات المطلوب (حتى 8 لوضع الكود).

## 6) ميزات جديدة كاملة

| الميزة | الملف | الوصف |
|---|---|---|
| رؤية بدائية | `VisionLoop` | يرندر HTML/CSS/JS (بما فيها Three.js/WebGL) بـWebView، يحوّله لفن ASCII (144 أو 256 رمز)، يطلب من النموذج يراجع ويصلح — حتى 12 محاولة |
| رؤية مستمرة | `VisionLoop.startContinuous` | لقطة كل 1.5 ثانية (~2.3% معالج) أثناء إنشاء الملف — مبني، بدون زر بالواجهة بعد |
| بحث ويب | `WebSearch` | Tavily API، المفتاح يُقرأ من ملف محلي مستثنى من git (`secrets.properties`) — **لا يوجد مفتاح مكتوب بأي كود** |
| اتصال التلفزيون | `TvLink` | بروتوكول WebSocket مطابق لـ`server.ts` الموجود — الجوال يعالج، التلفزيون يعرض بس |
| كاست النظام | `CastManager` | يتعرف على مرآة الشاشة الأصلية بأندرويد (نفس Settings > Cast)، بدون مكتبة خارجية |
| استديو التلفزيون | `tv_display.html` | محادثة + سجل تفكير حي + لوحة كود منفصلة (لأي رد فيه كود، مو بس عند إنشاء ملف) + معاينة ملفات + مايك (Web Speech API) + سجل أداء تاريخي مرسوم |
| تقييم 👍/👎 | `saveFeedback` | **سبب إجباري** (5 أحرف الأقل). 👍 أو 👎+تصحيح → `user_feedback.jsonl` (قابل للتدريب). 👎 بدون تصحيح → `user_feedback_review.jsonl` (غير قابل للتدريب أبدًا) |
| تحذير عدم تأكد | `Brain.answer` | رد قصير جدًا أو يكرر السؤال بس → "⚠ مو متأكد" تلقائيًا |

## 7) خط التدريب (`train-gru.yml`، GitHub Actions)

- **يستأنف من الأوزان المشحونة** (لا يبدأ من الصفر — كان هذا خلل فعلي صححته)
- معدل تعلّم افتراضي 0.0003 (كان 0.003 — قستها فعليًا: 0.003 تخرّب نموذج مدرّب، 0.0003 لا)
- نافذة التدريب (`--T`، ربط السياق أثناء التدريب) صارت قابلة للتعديل (كانت 96 ثابتة)
- **بوابة عدم التراجع:** يقارن (بت/حرف + نسبة خطأ الاختبار) قبل/بعد. يسمح بفرق سؤال واحد (الاختبار 14 سؤال فقط). لو أسوأ، يرفض ويحتفظ بالنسخة القديمة — **مُختبر فعليًا** على حالة نجاح وحالة فشل حقيقيتين
- كل تشغيل يسجَّل تلقائيًا بـ`benchmark_history.json`، يرسمه التلفزيون بدون ما تسأل

## 8) الأداء الفعلي المقاس الآن (نفس الأوزان، لا تغيير فيها)

اختبار 14 سؤال × 40 تكرار عشوائي، بمسار التطبيق الحقيقي (حارس النطاق → حاسبة دقيقة → النموذج):

| الإعداد | صحيح | هلوسة |
|---|---|---|
| الإعدادات القديمة (قبل هالمحادثة) | 11.3% | 74.5% |
| الإعدادات الجديدة (كل التعديلات أعلاه) | 15.4% (+37% نسبيًا) | 70.4% |
| بديل مقترح غير مُطبّق (اختيار حتمي، محاولة وحدة) | 21.4% (+90% نسبيًا) | 64.3% |

**صدق أخير:** كل رقم بالجدول ناتج عن **نفس 1.49 مليون معامل**، صفر تدريب جديد. التحسين كله من كيف
يُستخدم النموذج (حرارة، عدد محاولات، أخذ عينات)، مو من زيادة معرفته. "0% زيادة ذكاء فعلي" يبقى صحيحًا
لحد أول تدريب حقيقي عبر `train-gru.yml`.
